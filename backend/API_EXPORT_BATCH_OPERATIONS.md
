# API Documentation - Export & Batch Operations

## Overview

This document describes the new export and batch operation endpoints added to the WikiSource Verifier platform. These features allow admin users to export submission data and perform bulk operations on multiple submissions.

## Authentication

All endpoints require:
- Valid JWT token
- Admin role (`role: 'admin'`)

## Base URL

```
/api/admin/submissions
```

## Export Endpoints

### 1. Export Submissions

**GET** `/export`

Export submissions in CSV or JSON format with filtering options.

#### Query Parameters

| Parameter | Type | Description | Required | Default |
|-----------|------|-------------|----------|---------|
| `format` | string | Export format: `csv` or `json` | No | `json` |
| `status` | string | Filter by submission status: `pending`, `approved`, `rejected` | No | - |
| `category` | string | Filter by category: `primary`, `secondary`, `unreliable` | No | - |
| `country` | string | Filter by country code | No | - |
| `dateFrom` | string | Filter submissions from date (YYYY-MM-DD) | No | - |
| `dateTo` | string | Filter submissions to date (YYYY-MM-DD) | No | - |
| `search` | string | Search in title, publisher, or URL | No | - |
| `submitter` | string | Filter by submitter user ID | No | - |
| `limit` | number | Maximum number of records to export | No | 1000 |
| `offset` | number | Number of records to skip | No | 0 |

#### Example Request

```bash
# Export all approved submissions as CSV
GET /api/admin/submissions/export?format=csv&status=approved&limit=500

# Export submissions from specific date range as JSON
GET /api/admin/submissions/export?format=json&dateFrom=2024-01-01&dateTo=2024-12-31&country=US

# Export with search and filtering
GET /api/admin/submissions/export?format=csv&category=primary&search=news&limit=100
```

### 2. Get Export Preview

**GET** `/export/preview`

Get a preview of data that would be exported without actually generating the export file.

#### Query Parameters

Same as export endpoint, except:
- `limit` default is 100 (for preview)
- No offset parameter

#### Response

```json
{
  "success": true,
  "filters": {
    "status": "approved",
    "category": "primary",
    "country": "US"
  },
  "totalMatchingRecords": 1250,
  "previewRecords": 100,
  "previewData": [
    // Array of submission objects (same format as main data)
  ]
}
```

## Batch Operations Endpoints

### 1. Batch Update Submissions

**POST** `/batch`

Perform bulk operations on multiple submissions.

#### Request Body

```json
{
  "action": "approve|reject|delete|update",
  "submissionIds": ["id1", "id2", "id3"], // Optional if using filters
  "filters": { // Optional if using submissionIds
    "status": "pending",
    "category": "primary",
    "country": "US",
    "dateFrom": "2024-01-01",
    "dateTo": "2024-12-31"
  },
  "updateData": { // Required for approve and update actions
    "credibility": "credible|unreliable", // Required for approve
    "verifierNotes": "Batch approval notes", // Optional
    "category": "secondary", // Optional for update
    "wikipediaArticle": "https://en.wikipedia.org/wiki/Example", // Optional for update
    "verifierNotes": "Updated notes" // Optional for update
  },
  "batchNotes": "General notes for this batch operation" // Optional
}
```

#### Actions

| Action | Description | Requirements |
|--------|-------------|--------------|
| `approve` | Bulk approve pending submissions | `updateData.credibility` required |
| `reject` | Bulk reject pending submissions | None |
| `delete` | Bulk delete submissions | None |
| `update` | Bulk update submission fields | `updateData` with allowed fields |

#### Allowed Update Fields

For `update` action, only these fields can be updated:
- `category`
- `wikipediaArticle`
- `verifierNotes`

#### Example Requests

**Bulk Approve Submissions:**
```bash
POST /api/admin/submissions/batch
{
  "action": "approve",
  "submissionIds": ["507f1f77bcf86cd799439011", "507f1f77bcf86cd799439012"],
  "updateData": {
    "credibility": "credible",
    "verifierNotes": "Approved in batch review"
  },
  "batchNotes": "Monthly review batch - high quality sources"
}
```

**Bulk Reject by Filter:**
```bash
POST /api/admin/submissions/batch
{
  "action": "reject",
  "filters": {
    "status": "pending",
    "category": "unreliable"
  },
  "batchNotes": "Rejecting all unreliable sources pending review"
}
```

**Bulk Update Categories:**
```bash
POST /api/admin/submissions/batch
{
  "action": "update",
  "filters": {
    "category": "unreliable",
    "country": "US"
  },
  "updateData": {
    "category": "secondary",
    "verifierNotes": "Recategorized based on editorial review"
  },
  "batchNotes": "Category update for US sources"
}
```

#### Response

  "action": "approve",

  "performedBy": "admin",

      {
        "id": "507f1f77bcf86cd799439011",

## Error Responses

### 400 Bad Request
```json
{
  "success": false,
  "errorCode": "INVALID_INPUT",
  "message": "Either submissionIds array or filters object is required",
  "errors": [
    {
      "field": "action",
      "message": "Invalid action. Must be approve, reject, delete, or update"
    }
  ]
}
```

### 404 Not Found
```json
{
  "success": false,
  "errorCode": "RESOURCE_NOT_FOUND",
  "message": "No submissions found matching the criteria"
}
```

### 401 Unauthorized
```json
{
  "success": false,
  "errorCode": "UNAUTHORIZED_ACCESS",
  "message": "Access denied. Admin role required."
}
```

## Rate Limiting

Export endpoints are rate-limited to prevent abuse:
- Export: 10 requests per hour per admin
- Batch operations: 5 requests per hour per admin

## Data Validation

### Export Filters
- `dateFrom` and `dateTo` must be valid dates in YYYY-MM-DD format
- `limit` must be between 1 and 10000
- `offset` must be 0 or greater
- `format` must be either 'csv' or 'json'

### Batch Operations
- Maximum 1000 submissions per batch operation
- For `approve` action, credibility rating is required
- For `update` action, at least one valid field must be provided
- Submission IDs must be valid MongoDB ObjectIds

## Points System

Batch operations follow the same point system as individual operations:
- **Approval**: +25 points for submitter if credible, +10 if unreliable
- **Rejection**: No points for submitter
- **Verification**: +5 points for verifier regardless of outcome
- **Update**: No points awarded (informational operation)

## Audit Trail

All batch operations are logged with:
- Admin user performing the operation
- Timestamp
- Action taken
- Number of submissions affected
- Success/failure counts
- Notes provided

## Best Practices

1. **Export Operations**:
   - Use appropriate date ranges to avoid timeouts
   - Use preview endpoint to check data before export
   - Consider exporting in chunks for large datasets

2. **Batch Operations**:
   - Test with small batches first
   - Use filters instead of large ID arrays when possible
   - Provide meaningful batch notes for audit purposes
   - Monitor success rates in the response

3. **Performance**:
   - Large exports (>5000 records) may take several seconds
   - Batch operations are processed sequentially for data integrity
   - Consider running large operations during off-peak hours

## Frontend Integration

The frontend provides a user-friendly interface for these operations through the "Export & Batch" tab in the Admin Dashboard. Users can:
- Preview data before export
- Apply various filters
- Download CSV or JSON files
- Perform batch operations with confirmation dialogs
- View operation results and statistics

## Troubleshooting

### Common Issues

1. **Export Timeout**: Large exports may timeout. Use smaller date ranges or limits.
2. **Batch Operation Fails**: Check that submissions are in the correct status (e.g., only pending submissions can be approved/rejected).
3. **Permission Denied**: Ensure the user has admin role assigned.
4. **Rate Limit Exceeded**: Wait before making additional requests.
